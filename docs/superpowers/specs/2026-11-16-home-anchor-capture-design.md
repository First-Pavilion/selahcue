A viewport-relative target position of 1722 or 1686 does not establish missing-target lookup, failed dispatch, interrupted motion, or changing layout. Choose targeted capture: intercept the two browser methods used by the established router path, collect bounded scalar observations, and sample at the existing assertion. Broad tracing/video/network logging increases data and perturbation without answering the narrow first question. An immediate timeout, motion, routing, font or layout change would change the failing experiment before its mechanism is known. Neither alternative is in scope.

This is a diagnostic patch, not an anchor fix. An instrumented pass remains a pass with historical cause unknown. Never declare an observed lookup to be uniquely attributable to Vue Router: the wrapper observes external calls for the exact target ID, without stack capture or caller identification. Source establishes the likely caller, not runtime identity.

## Controller and measurement contract

The JavaScript source evaluates to `installHomeAnchorCapture(options)` where options contain only a validated 32-lowercase-hex `actionId`; browser globals come from the page. It returns a bounded arm snapshot and installs `window.__scHomeAnchorCapture` with `finish(measureTargetTop)`, `dispose()` and the same action ID. Collision means unavailable; never replace an unknown pre-existing controller.

The Python entry point is `run_pricing_anchor_check(page, run, *, engine: str, target_top_js: str, provenance: dict, sink) -> None`. The caller retains the Pricing goto and font-ready wait. The adapter installs the observer immediately before the unchanged click. The adapter executes click, URL wait, 1200 ms wait, final measurement and original `run.near` once, in that order. There is no added page evaluation between click and final measurement. On instrumentation installation failure, perform the same original action and original `TARGET_TOP_JS` measurement; label instrumentation unavailable. Do not run the action again.

At the original measurement position, execute one page evaluation whose callback passes the unchanged `TARGET_TOP_JS` expression to `controller.finish`. `finish` first stops observation/restores owned wrappers, then invokes that callback once before any extra geometry read. It stores the returned top and takes final `scrollY`, target top again only if needed for supplemental consistency (prefer reuse), navbar bottom and computed numeric gap. Use the original returned top for the original assertion. A target absent at that moment stays null; never substitute an earlier successful value. If supplemental sampling fails, return the already acquired original top with incomplete diagnostics. If the original measurement throws, rethrow the identical error; do not retry the measurement. If the controller is missing/replaced, evaluate the original callback once in that same evaluation and return an incomplete envelope.

Supplemental final document-relative top is `originalTargetTop + finalScrollY` when both finite; report its sampling limitation because the getter and scroll position are sequential reads. Record the requested destination and final viewport independently; no earlier target geometry is added. Consequently this capture cannot directly prove a change in document-relative target position since route dispatch. A mismatch can motivate a separately designed geometry experiment; it cannot establish layout shift by itself.

## Passive observation and forwarding

Before arming, retain exact original own-property descriptors and method references for `document.getElementById` and `window.scrollTo`. Restore the descriptor if originally own, otherwise delete the owned shadow property. Installation is transactional: unwind any partial installation. At cleanup, restore only if the current property is still this observer's wrapper; report `wrapper_replaced` otherwise, without overwriting somebody else's replacement. Cleanup is idempotent and always attempts every removal even if one fails.

Any pre-forward timestamp read is separately guarded and cannot prevent forwarding. Use a projection reentrancy guard so hostile projection hooks cannot recursively collect diagnostics. Use ordinary functions and `Reflect.apply(original, this, args)`; never bind, normalize, clone or rewrite native arguments. Save original result/error, then run diagnostic projection in a separately guarded block, then return or rethrow the exact saved value/object. Observe non-target getter calls only by forwarding, with no record or coercion. Strictly compare the first argument to the literal `how-it-works`; do not call `String` or any user conversion. Internal presence probes use the saved original with `document` as receiver and do not enter the wrapper. Timestamps use one captured monotonic `performance.now` origin; no wall-clock ordering inference.

For scroll calls retain argument count (0..16, otherwise `many`), overload (`numeric`, `options`, `other`), entry/return timestamps, finite numeric top/left and allowlisted behavior (`auto`, `instant`, `smooth`, `other`, `absent`), plus returned/threw. Numeric overload values are projected without conversion. For the options overload, inspect only own descriptors for `top`, `left`, `behavior` after native forwarding, and accept data descriptors with primitive values only. Never read accessor values, enumerate properties, stringify objects or emit arbitrary strings; mark unsupported/missing/accessor/projection-error fields unknown. Descriptor inspection on a Proxy can invoke a trap: catch failures and retain an explicit projection-quality field. This is a known observation limitation, not a claim of perfect transparency for hostile Proxy side effects. Label option values `post_call_own_data`, not a guaranteed snapshot of values consumed by native conversion. The real router's plain options object is the supported diagnostic input. Tests must prove no getter is invoked by the observer and a throwing proxy trap cannot replace the native result/error.

Add one passive capture-phase click listener that recognizes only the known anchor href and records the event without preventing it. Report click `isTrusted` as a boolean. Add passive scroll, hashchange, popstate, visibilitychange and pagehide listeners. Route labels are only `pricing`, `home_anchor`, `other`; hash labels only `none`, `how_it_works`, `other`. Read location only into those enums; never export its string. Observe route labels at arm, click, relevant method/event callbacks, mutation callbacks and finish. Store only label changes, with first/latest observation times and dropped count. Vue Router pushState does not necessarily emit hashchange/popstate: no history wrapper is added, so these are observation timestamps, never exact route commits.

The mutation observer watches child-list/subtree changes under `#app` (fall back to document root), performs one saved-original target presence probe per callback, and disconnects on first presence or its callback cap. Do not traverse mutation records or retain nodes. Presence is first observed presence, not exact insertion time. Scroll captures only first/latest timestamp and `scrollY`, count and extrema through the callback cap; no unbounded samples or per-event layout queries. No requestAnimationFrame loop or observer timer. Visibility/pagehide use bounded enum fields and counters, not event objects.

Final completeness reports include installation, original action stages, target measurement acquisition, same-controller/document identity, wrapper ownership, observer limits, projection quality, cleanup and terminal emission. Limits and unsupported inputs are visible even on an assertion pass. An observer missing on final evaluation indicates document replacement or removal; distinguish only what is actually observed. Start/end matching on action ID proves the same closure survived, not that the observer saw every browser-internal scrolling cause.

## Receipts, provenance and failure behavior

Start receipt is flushed before arming; terminal is flushed after original assertion or in adapter `finally` on an action exception. Each is allowlist-projected anew on the Python side. Preserve a re-raised action exception with its original traceback. A broken sink or diagnostic exception must not create an extra assertion, suppress a failing assertion, change the harness return status, or retry the action. Mark unavailable where a safe receipt can still be emitted; otherwise the archived start alone exposes incompleteness. No raw exception text.

Schema includes `schema_version:1`, fixed marker `home_anchor_capture`, `phase:start|terminal`, fixed engine enum, action ID and original assertion outcome `pass|fail|not_reached`. Fixed reason enums: `install_failed`, `controller_missing`, `wrapper_replaced`, `lookup_limit`, `command_limit`, `route_limit`, `scroll_limit`, `mutation_limit`, `counter_saturated`, `projection_unavailable`, `sample_incomplete`, `cleanup_incomplete`, `action_exception`, `export_limit`. Use null for unknown scalars. Every numeric value must be finite and bounded to absolute 1,000,000,000; out-of-range becomes null plus incomplete, not silently clamped into evidence.

Record validated contextual provenance: 40-hex `GITHUB_SHA` labelled `github_context_sha` (not independently verified checkout), decimal run ID/attempt up to 20 characters, engine, strictly parsed browser version and installed Playwright version (at most 64 ASCII numeric/dot characters), SHA-256 of the exact helper and Home harness read from disk, each lowercase 64 hex. Unknown values are null. Compute this outside the click critical section. No arbitrary environment dump, commit message, branch, command line, absolute path, user agent or URL. The controller separately archives verified tested checkout/merge parents, source head/tree, run/job IDs and pinned browser install identity from the normal CI evidence. Do not equate `GITHUB_SHA` alone with that verification.

Arm and finish snapshots include allowed path/hash labels, visibility enum, font status enum, reduced-motion boolean, `innerWidth`, client width and height (initial reads before the click), scroll position, and target presence. Arm confirms Pricing label and target absence without gating or waiting. End keeps the same token/closure check and effective viewport scalars after original measurement.

Receipt serializer measures ASCII encoded bytes including newline. If over 24 KiB, replace detailed arrays with a bounded terminal envelope retaining identity, original outcome, counts and `export_limit`; set completeness false. Never truncate JSON bytes or silently drop records. This is export incompleteness separate from observation limits.

## Behavioral controls and acceptance

Use Node vm fixtures to run the exact shipped helper. First establish a minimal pass-through implementation so RED is a missing behavioral observation assertion, not a missing import/helper. Controls cover call receiver/argument identity and exactly-once forwarding, original return and thrown-object identity, non-target ID coercion avoidance, descriptor/getter safety, observer-failure isolation, route changes without hash events, missing-then-present targets, saturation and every cap, no geometry reads before final callback, measurement first/exactly once, transactional install, replaced wrappers and idempotent cleanup. A simulated successful/failed alignment demonstrates record interpretation only, not real engine rendering.

Use stdlib Python fake-page controls for exact click/URL/wait/sample order and values, the unchanged 95/2/message assertion, diagnostic failure fallback without action replay, original measurement exception without retry, cleanup after click/URL exceptions, stdout failure preserving action results, contextual provenance validation and oversized/malicious receipt rejection. Tests execute no Playwright import, browser, app or server. Include an AST/static review of the small harness call-site diff as supplementary evidence, not the primary behavioral test.

Acceptance is reviewed bounded diagnostics with unchanged action/gates, fixture RED/GREEN evidence, and one archived normal hosted capture. Chromium in that normal Home invocation is the observation control; no extra engine invocation is added. A failing trace can narrow investigation only within its completeness limits. A passing trace, a missing receipt or an ambiguous command is not root cause. No production remediation is selected from this design alone.
