# Controlled pilot runtime and deployment

The owner has approved a manually deployed controlled pilot, all three desktop platforms and direct-provider cloud features, with readiness targeted for 2026-11-15 16:36 UTC. This slice supplies a real production API process and the requested repository-root DEPLOYMENT.md. Cloud grants, native account integration and compiled public entitlement trust are separate dependent slices.

The API image currently starts Django runserver. Replace its default with Gunicorn serving selahcue_api.wsgi:application on port8000. Keep development Compose's explicit runserver override. Use a fixed conservative baseline of two sync workers,30-second worker and graceful shutdown timeouts, and no access log that might record account/reset query tokens. Django’s explicit trusted-proxy setting determines the secure scheme. Set Gunicorn’s `forwarded_allow_ips` to an empty string, which normalizes to an empty allowlist, and set `secure_scheme_headers={}`. Do not preload Django state across worker forks. The deployment guide must call the CSRF route liveness only and require separate database/cache/worker/mail checks.

Pin Gunicorn27.0.1 and lock its resolved graph. Engineering ruling: permit a package-specific exception to the existing14-day resolution age only for this exact pin. The upstream27.0 release fixes HTTP request framing/header validation, and27.0.1 fixes shutdown request handling; using the newer exact pin avoids introducing the known older parser behaviors. Preserve the age gate and all unrelated dependency versions. Sources: https://github.com/benoitc/gunicorn/releases/tag/27.0.0 and https://github.com/benoitc/gunicorn/releases/tag/27.0.1, inspected2026-11-14. Cost if wrong: a reversible isolated dependency/runtime regression, caught through process-level probes and reviewed before merge.

Manual deployment remains owner-operated. No production database, provider account, Coolify application or website is changed by this slice. No provider/signing private key enters an image, installer or repository. Existing development Docker workflows and source tests must continue to work.
