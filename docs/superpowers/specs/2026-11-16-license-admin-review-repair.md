## Free writer and lock ownership

Its safe composition is rollback of all expiry/status/token/receipt/inner audit changes followed by one durable `FreeRenewalDenied.audit()` from the owning outer handler. ## Durable staff generation

Add `staff_extension_generation = models.PositiveBigIntegerField(default=0)` to `AppLicenseKey` and `DeviceToken`. Every successful, non-replayed staff extension increments the locked licence generation once, in the transaction containing expiry/status and SUCCESS audit. Audit before/after includes the corresponding generations. Failure, refusal and replay do not increment. `_new_device_token` snapshots the locked licence generation for all issuance paths. At bigint maximum, refuse safely before mutation.

Pending staff renewal is `token.staff_extension_generation < licence.staff_extension_generation`; equal clocks and expiry changes cannot affect the predicate. A token generation greater than its licence's is invalid state and refuses mutation. Multiple extensions coalesce into one replacement at the latest generation. Pure Free changes never advance either generation. Free may not extend a pending-generation bearer in place: capable clients rotate under locks; legacy clients retain their original token expiry and pending generation. The licence's own eligible automatic renewal may still occur under its existing policy.

Migrations are separate app-state operations:

- `license_keys/migrations/0004_staff_extension_generation.py`: own AddField, depends on licence `0003_free_license_lifecycle`.
- `devices/migrations/0005_staff_extension_generation.py`: own AddField, depends on devices `0004_receipt_database_set_null`, licence `0004_staff_extension_generation`, and the existing audit migration needed by its historical model. Then data-backfill using historical models.
- For the normal current-target baseline both values are zero. For pre-existing SUCCESS `license_key.extended` audit records targeting `app_license_key`, conservatively set the referenced licence's zero generation to one; all existing token generations remain zero. Preserve expiry, status, audit and receipt data. Do not infer historical token ordering from timestamps. This may require one extra rotation on an imported historical licence and cannot miss a pending extension.
- Invalid/nonexistent audit target IDs are ignored safely, not cast through an unsafe bulk SQL integer conversion. Process in bounded batches or an equivalent set-based query with safe target handling. Only update zero generation; never reset a nonzero generation. No historical audit is fabricated. Operational rollback retains these columns and data.

## Refresh API and internal interfaces

Keep `devices.services.refresh_license(presented_token: str, *, token_rotation: str | None = None) -> LicenseRefreshResult`. Accept absent capability or the exact value above; other provided values refuse validation. Keep `LicenseRefreshResult.full_token` optional and its existing `activation_token` response field, which is only non-null for a negotiated replacement. No-store applies to replacement responses and relevant errors. Preserve existing bearer-header/body-token compatibility.

The ordinary non-managed/equal-generation path authenticates once with the current joined query, probes the indexed Free marker and counts active devices. It takes no row locks and does not authenticate twice. A staff change after that read may appear on the next refresh. Mutating paths re-read generation/device/token/commercial validity and plan allowance under locks; they may not trust the fast-path snapshot. Managed paths start with org locking. Recheck token liveness after eligibility waits and immediately before issuing a replacement if intervening work can wait.

The Free extraction, if used, is `renew_free_license_for_device_under_locks(customer, license_key, device, locked_token, *, now: datetime | None, request_id: str, allow_token_catchup: bool = True) -> RenewalResult`. It assumes org/licence/device/token locks, acquires marker/assignment eligibility locks, samples time, refuses a dead token, performs eligible licence renewal and optional in-place token catch-up, and propagates `FreeRenewalDenied` without auditing. The existing public wrapper retains its signature and owns its original transaction/denial handling for remaining callers. Device refresh supplies `allow_token_catchup=False` when staff generation is pending and retains the outer denial owner.

Staff rotation uses the existing remint primitive, plan allowance and masked audit, superseding all non-revoked credentials for that installation. A dead token never authenticates to rotation. Concurrent attempts produce one winning replacement; the losing original bearer is rejected.

Password and token handling remain confined to the existing secret-bearing channel, with no logs/metadata storage.

For a lost rotating refresh there may be no pending activation; the established public ID plus fresh authorized replacement action is sufficient. Internal `CascadeBatchResult(changed, examined, next_cursor, exhausted)` drives progress; preserve public `cascade_license_revocations(batch_size=500) -> int` functional compatibility.

Check monotonic deadline before selecting pages/candidates. PostgreSQL transaction-local lock timeout is 1 second; statement timeout is at most 5 seconds, clamped to remaining budget and applied to selection/rechecks/audit too. Catch database timeouts outside the atomic block. Application cutoff 225 seconds; task soft limit 235 and hard limit 240, scoped to this task. One high-water pass per invocation; only productive cutoff enqueues at most one continuation, with 60-second broker expiry. Blocked-only work returns for minute beat; periodic scheduled deliveries also expire after 60 seconds. Preserve late acknowledgement and existing broker socket bounds. Real prefork/PostgreSQL/Redis verification, not direct calls/fake clocks, establishes timing and overlap behavior.
