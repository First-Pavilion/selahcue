# Ongoing Free licence renewal — technical policy

14 November 2026. Documentation proposal, accepted by the coordinator as an engineering implementation of the owner's explicit ongoing Free release. No code, provider configuration or account state was changed.

## Rule

Issue an initial Free licence for **365 days**, lazily at the first eligible, email-verified ADMIN activation. Renew a managed Free licence when its remaining validity is **30 days or less**, to `now + 365 days`, through authenticated `POST /v1/license:refresh` or a fresh verified ADMIN activation/recovery operation. Re-observing a completed activation receipt is read-only for both live and dead original-result tokens; it never extends licence/token dates, changes lifecycle state or writes a renewal audit. Use server UTC instants and an injected clock. No renewal adds another year on every request, creates another device slot, resets the weekly ledger or provisions a provider resource. There is no business expiry or trial conversion.

Store an explicit `FreeLicenseLifecycle` record, unique per organisation and licence, with policy version and automatic-renewal eligibility. It distinguishes licences issued by this trusted service from staff-issued or legacy licences. A missing marker is not permission to convert, replace or revive an existing licence. The org lock and the existing no-overlapping-valid-key invariant govern both initial issuance and renewal.

A live device refresh first authenticates its existing token. Inside the renewal transaction, recheck org, licence, device and token eligibility. Extend only the presented token if it is still ACTIVE and unexpired, to the renewed licence's expiry. This avoids making an actively used device sign in merely because its original token expiry arrived. Do not change token material, issue a replacement token, touch the OS store, or extend another device's credentials. Return the updated dates, then let the existing manifest fetch/signature/cache path obtain a fresh claim. This intentionally changes the current refresh service's “pure read” description for managed Free licences; document and test that change.

A device absent beyond its token expiry must sign in as a verified ADMIN. The trusted lifecycle service renews the same eligible Free licence first; completed G1 then remints for the same ACTIVE device fingerprint. That consumes no extra slot and needs no reinstall. Dead, missing or revoked tokens never authorize renewal themselves. Existing enrollment-key activation remains governed by its existing proof and eligibility rules; it must not acquire an unauthenticated Free-licence creation path.

Only expiry of an otherwise eligible managed Free licence is automatically recoverable. A suspended/revoked licence, disabled organisation, inactive/revoked device, or administratively disabled lifecycle record remains denied. Do not issue a fresh licence to evade such a denial. For self-service accounts still bearing the old `TRIAL` org label, activation may perform the audited one-time transition to ACTIVE only after verified ADMIN eligibility; all suspended/cancelled/churned/archived org states remain excluded. The legacy `CustomerOrg.plan` label is never an entitlement source.

## Why this window and its cost

365 days keeps a routinely used Free installation stable through ordinary offline periods. A 30-day lead gives several ordinary foreground refresh opportunities before expiry, without a background renewal service or nightly write across every account. Long-absent devices can recover through the already-built sign-in/remint contract. There is no exact cadence promise if a device stays offline.

The tradeoff is **up to 365 days of offline validity for previously signed Free claims**, subject to the manifest's actual shorter expiry if one is configured, and an occasional sign-in for a dormant device whose token expired. Revocation cannot retract an already cached offline signature without connectivity. This is not 365 days of provider cloud spending: every new cloud admission checks live server eligibility, the current weekly allowance and provider readiness; ephemeral credentials retain their separate limitations. Local presentation and saved show data must remain usable when the cached entitlement expires or renewal fails.

Tests must cover the 30-day boundary on either side, exact expiry, leap-day dates using durations rather than calendar-year assumptions, duplicate concurrent refresh/activation, live-token extension, dead-token refusal, unchanged unrelated token expiry, suspended/revoked state, recovery after a year away with the same fingerprint, unchanged weekly counters, and failed refresh with uninterrupted local presentation (native owner acceptance).

No additional business choice is needed for the validity numbers. Notes now use the selected ADR0028 C fallback; its separate operational budget and qualification remain release work. No A raw-token extra-unit envelope is required for C. This Free renewal rule changes neither STT provider exposure nor notes accounting.


## Task 1 execution rulings

- Preserve the no-overlap invariant. If extending the exact managed Free licence would overlap a current or future competing key, refuse renewal without changing dates, reminting, allocating a device or choosing another licence. Test successful recovery in a nonconflicting window and a separate competing-window refusal. The earlier competing-licence test requirement proves no retargeting; it does not override overlap protection. Cost if wrong: explicit support/recovery work instead of silently changing the device's licence.
- Reuse the existing CUSTOM key type with explicit catalogue FREE assignment and a managed lifecycle marker. Do not add a staff-facing key-type enum solely for this lifecycle. Cost if wrong: reversible internal representation; the commercial plan remains explicitly Free.
- A presented, still-live token may catch up to its eligible active managed licence's existing expiry when the token has at most 30 days remaining, even when another device or ADMIN already renewed the licence. This token-only update does not extend the licence again, issue a new token, affect another token or reset quota. Recheck org, licence, device, token and enabled marker under the same lock order; record a safe token-only audit. Dead tokens still require G1. Cost if wrong: additional validity for the authenticated token within the already granted licence horizon; prevents one earlier renewal from stranding other legitimate devices.
- A disabled lifecycle marker blocks automatic date/token extension and replacement. It does not itself revoke an already-valid commercial licence. Disabled or suspended orgs and revoked/suspended/inactive devices never gain renewal through this policy. Preserve existing unmarked/staff activation and invalid-status reporting semantics.
- A durable completed operation whose original token is dead must not renew or remint on replay. For an expired managed Free licence, a read-only completed identity proof is allowed only on the verified-ADMIN route after active-org, exact receipt/path/digest and bound-device checks, with revoked/suspended/disabled licence or inactive device still refused. It carries no token and changes no dates. A separate explicit recovery may then renew the exact licence subject to the no-overlap rule. Enrollment-key presentation alone gains no renewal authority. Cost if wrong: an authenticated display of an already recorded public device identity; avoids losing the target after a long absence while preserving the explicit recovery boundary.
