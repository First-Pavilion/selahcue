# Hosted Native Fixture Proof Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Root retains the single source-writer slot and serial assignment. Steps use checkbox (`- [ ]`) syntax for tracking. This document is proposed for scoped builder re-review and root acceptance, not an execution assignment.

**Goal:** Produce one current, independently checked macOS arm64 native fixture receipt without lifting the local paging hold.

**Architecture:** A single manual/main-only workflow provisions a disposable official pinned toolchain/public-crate seed, then runs the unchanged fixed-path builder and finite synthetic comparator offline. Existing Linux workflow validators enforce the complete narrow exception, and receipt-only artifacts carry the result back to root.

**Tech Stack:** Python>=3.11 standard library, existing PyYAML workflow checks, GitHub Actions `macos-26`, exact Rust/Cargo 1.98.0 aarch64, unchanged Rust synthetic adapter.

**Spec:** [Proposed hosted amendment](2026-11-15-hosted-native-proof-amendment.md). Read it together with the accepted recovery amendment and root metadata/fixture receipts it names. This plan relies on its full constants, literal paths, construction formulas and independently recovered hashes.

Root accepted the two narrow dispositions in [the independent builder check](hosted-native-proof-builder-check-20261115.md): honest separation of outer stream bounds from the frozen builder's internal Cargo buffering, and an explicit post-upload cleanup interface. These clarifications require no new user question. All other accepted identities, limits, constructors, oracles and cost boundaries remain unchanged; scoped builder re-review and root acceptance are still pending.

- No implementation until root accepts the proposal and assigns the source slot; do not collide with current installer source work. Do not revert others' changes.

- Fixed original O/S/toolchain/registry/spec/pin paths, normative commit `1ea22e1ce6e52ab8aa2e0fd83fda1c9d90b094da`, all 102 source hashes, owner and scratch locks, immutable builder/main/manifest bytes and56 registry tuples remain exactly as the spec states.
- Exactly1 build, `--frozen --jobs 2`, no `--resolve`; eleven sequential native batches/1,111 frames and47 pure rejects. Never replace historical matrix/wrapper expectations or calculate expected outputs with the new binary.
- Setup network only for official pinned Rust/public lockfile crates; no personal cache/config. Native build/check network denied. No provider/corpus/private payloads, app signing, Tauri launch or installer build.
- One initial root dispatch after main review/merge only; no automatic reruns. Setup 300 seconds/build 600 seconds/proof 120 seconds, overall 20 minutes including finalization. Resource admission and postchecks are mandatory.
- Local compilation hold and Q absence remain unchanged. Historical native evidence, this new adapter proof, bridge source extraction and installed-app acceptance remain separate claims.

## Review Focus

- A malformed exception shape must never disable the all-workflow Mac ban: Task3 mutation tests cover renamed file, missing runner, extra job and YAML on/True handling.
- Legitimate Unicode/API values must retain their exact bytes while persistence truncates only at its known byte boundary: Task1 translation, Unicode and scalar fixtures cover these independently.
- Corrupt or reordered framing must fail before an expensive build: Task1 checks pinned input, wrapper construction and forged golden defenses; Task2 denies build after failed preparation.
- Existing/symlinked staging state or inherited credential configuration must not contaminate the proof: Task2 exclusive-path and poisoned-environment tests require refusal with zero builder invocations.
- Timeout, paging, partial output or artifact loss must never yield a pass: Task2 fake process/resource tests and Task4 receipt readback require complete postchecks.
