### Task 1: persistent install identity and honest local Account view

**Create:** `implementation/desktop/crates/selahcue-operator/src/account/{mod.rs,state.rs,tests.rs}`. **Modify:** operator `Cargo.toml`, `Cargo.lock`, `src/main.rs` only for module declaration and controller state.

**Interfaces (new, proposed):** `AccountMetadataStore::new(PathBuf)`; `load_or_create(device_credential: CredentialPresence) -> Result<AccountMetadata, AccountStorageError>`; `save(&AccountMetadata) -> Result<AccountMetadata, AccountStorageError> (use the committed revision returned by save)`. `AccountMetadata` holds `schema_version`, random install fingerprint, normalized display/platform/version data, optional activated public ID, skipped-setup flag, and optional `PendingActivation { path, idempotency_key, identity }`. It holds no password, enrollment key, session/device token or raw HTTP response. `AccountView` is the sole serializable UI projection: revision, setup state, device state, entitlement state, optional display labels/counts/times, operation state, stable safe error code and pending-cleanup boolean. Optional unavailable fields stay absent, never fabricated.

**Credential-presence seam (no secret value):** inject `enum CredentialPresence { Missing, Present, Unavailable }`. `Missing` means the OS secret store positively confirmed that the native device-token entry is absent; `Present` means that entry exists; `Unavailable` covers locked/denied/failing storage or an otherwise unknown result. Never convert an OS-store error into `Missing`. The metadata store does not read credentials itself and receives no token, password or session. Its locked decision table is:

| Metadata read | Credential presence | Result |
| --- | --- | --- |
| Existing, valid metadata | Any of the three | Load the existing identity unchanged; unavailable custody can be rendered separately. |
| File genuinely absent | `Missing` | Generate and atomically persist one new identity. |
| File genuinely absent | `Present` | Return `IdentityRecoveryRequired`; create no fingerprint or metadata. |
| File genuinely absent | `Unavailable` | Return `CredentialPresenceUnavailable`; create no fingerprint or metadata. |
| Corrupt, unsafe, oversize or unreadable metadata | Any of the three | Return the corresponding metadata error; never reset identity. |

The Slice-3 controller obtains this non-secret presence result from native device custody on its worker immediately before initialization; mocks inject it directly in Slice 1. Treat only an actual not-found metadata result as absence. Keep the create-if-missing decision and winner re-read under the existing metadata lock. All managed activation paths must persist identity before any device credential, so concurrent ordinary activation cannot introduce a credential for an identity that was never stored; a caller must not cache a `Missing` result across retries/restarts or credential mutations. This is a presence snapshot, not an atomic transaction with the OS store, and must not be described as protecting against arbitrary external keychain/filesystem changes.

#### Clock and renewal acceptance detail for Task 3

**Clock decision evidence.** Cached task `/private/tmp/selahcue-native-account-task-86ajy7anx.md` requires tolerance on `issued_at` / `not_before` and a beyond-tolerance test, but supplies no number. FR-524 (`docs/product/prds/SelahCue-Platform-PRD.md:203`) requires a documented bounded tolerance and “cannot verify — renew/refresh when online” when the clock is wildly wrong; the manifest design (`docs/superpowers/specs/2026-08-13-entitlement-manifest-design.md:258,317`) leaves the bound to the client slice. No decided numeric licensing tolerance was found. LAN replay tolerance is a different contract and must not be imported. **Engineering recommendation for implementation/review: `LICENSE_CLOCK_SKEW = Duration::from_secs(120)` (two minutes), applied only to future `issued_at` / `not_before`.** This is a newly documented engineering choice, not a recovered owner decision or a new approval gate. It absorbs modest workstation clock drift without concealing larger date/time errors; no observed device-clock distribution is available, so the value is a reviewable bounded default rather than an empirically established requirement. Too small a bound produces avoidable “cannot verify” status and refresh/clock-correction prompts on otherwise authentic manifests. Too large a bound accepts a signed future lower boundary earlier: this proposal permits at most two minutes of such early temporal acceptance, while still requiring valid signature/identity and an unexpired manifest. That tradeoff is confined to account status in this task; it neither authorizes new grants nor changes output enforcement. The value does not extend manifest/license expiry, token validity, cache retention or renewal grace. A genuinely wrong clock remains degraded with core presentation usable. Record this constant and rationale in the implementation evidence and pin exact boundary tests; change it only deliberately with updated tests, not through a user-editable config or network response.

**Proposed temporal algorithm, using the recommended 120-second constant:** use exact `(seconds,nanos)` comparisons and checked time arithmetic. Signature/identity/cache-order checks run unchanged first. A manifest is `future_or_clock_skew` if either signed `issued_at > now + skew` or `not_before > now + skew`; otherwise the bounded allowance applies to those two lower boundaries only. At `now >= manifest.expires_at`, show signed cache as expired/unavailable and offer refresh; no skew-based expiry extension. Track `license_expires_at` separately for renewal-needed display, without converting it into output enforcement or inventing a grace grant. A signed past record may remain available as historical display with explicit age/expiry; do not label it current. Unknown signer, corruption and identity failure remain unverified, with no trusted metadata projection. A wrong local clock cannot be conclusively diagnosed from a future/expired document alone: use “cannot verify current entitlement; check date/time and refresh,” with renewal guidance when signed/online license facts support it. Keep core presentation and emergency controls running in every state.

**Temporal tests:** inside 120 seconds, exactly at 120 seconds and one nanosecond beyond for each of `issued_at` and `not_before`; one nanosecond before/exactly at/after manifest expiry; license expiry independent of manifest expiry; same-second fractional boundaries; wildly forward/backward clock; arithmetic overflow refusal; restart with expired/future signed cache; failed remote refresh retains truthful stale status; successful refresh updates status; unverified cache shows no trusted plan. Test with an injected clock, not sleeps. An expiry caused by a badly forward clock must not be presented as proof that the server license expired.

**Renewal contract:** retain one install fingerprint and public ID across all paths; no reinstall, random replacement fingerprint or extra seat. The task's broad “automatically via G1” phrasing must be evidenced against the actual authentication contract, not interpreted as dead tokens authenticating themselves.

| Situation | Required behavior and acceptance |
| --- | --- |
| Device token remains valid; license had expired and is renewed | On next Account-page/foreground/explicit refresh, read current status and fetch/verify/cache the renewed manifest automatically. No new sign-in, activation or remint is needed. Test expiry/status → server renewal → refresh success → restart from renewed cache, with unchanged token/fingerprint/device/seat count. Construct a source-valid fixture whose token remains live; ordinary token lifetime is tied to its issued license expiry, so this path is conditional, not a promise for every natural expiry. |
| Device token expired/revoked, or no usable token remains server-side | `license:refresh` / manifest 401 becomes a stable re-authentication-needed state. A valid stored ADMIN account session, if still present, can authorize G1; otherwise request ordinary sign-in or enrollment key. G1 uses the same fingerprint, returns `created=false`, `reminted=true`, and a new show-once token. Persist before clearing account session, then refresh/fetch/cache. Successful normal activation already cleans up its account session, so silent remint is not generally available. |
| Local token missing but the server still has a usable live token | Same-fingerprint replay returns no token; preserve `MissingLocally` and offer actual administrator/server recovery. Repeated sign-in/new idempotency must not be advertised as recovery. |
| Device itself revoked, license still inactive, or plan no longer admits this device | Preserve safe refusal and identity. Token remint is not authority to reactivate a revoked device or bypass license/seat policy. |

Joint G1 evidence must include real API integration for expired-token renewal and cascaded-revoked-token renewal, enrollment and ADMIN-session paths, unchanged device count/public ID/fingerprint, old-token rejection, one-seat license, new token saved before cleanup, and recovery after app restart.
