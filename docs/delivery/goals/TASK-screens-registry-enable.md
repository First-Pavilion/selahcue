## Objective

The Screens page (86ajq321f) ships the app-menu shell, per-screen role badges, per-screen theme pickers, and live preview canvases — but the **screen set is a fixed const** (`AUDIENCE_SCREENS = ["main","lower-third","stream"]`, controller.rs:190, with an explicit "dynamic Add/Delete is a follow-up" comment). The operator UI itself advertises **enable/disable and add/delete as "arrive next".** This batch delivers that: turn the fixed const into a **bounded, persisted, deterministically-ordered SCREEN REGISTRY** whose entries carry `{ id, role, enabled, deletable }`, so an operator can (a) **enable/disable** any screen (mute the lower-third mid-service; black the confidence monitor), and (b) **add** a virtual audience-class screen (a second stream feed) and **delete** it — the right-aligned Enable toggle + "+ Add screen" of NAV-IA-spec §3. Physical NDI/SDI/stream transport DELIVERY stays an honest R-later affordance (a virtual screen composes + previews on-demand; the Output-target + Format selectors stay read-only "arrives later" — never faked).

## Scope

### In scope

- **Registry (`selahcue-app`):** replace the const with a bounded, ordered `ScreenRegistry` — entries `Screen { id: String, role: ScreenRole, enabled: bool, deletable: bool }`. `ScreenRole { Main, LowerThird, Stream, Stage }` (Audience-class = Main/LowerThird/Stream). Seed built-ins main/lower-third/stream/stage (all `deletable=false`, `enabled=true`). **`MAX_SCREENS` hard cap** (16) → a bounded-memory test. Deterministic order (an explicit ordered structure, not a `HashMap`). The per-screen theme map keys stay a SUBSET of the registry ids.
- **Enable/disable:** `Command::SetScreenEnabled { screen, enabled }` toggles `enabled`. A **disabled** screen: `compose_screen`/`GetScreenFrame` return the existing safe all-black frame (no new `None`/panic path); the desktop main window blacks when `main` is disabled and the stage window blacks when `stage` is disabled (a small honest per-screen mute, distinct from global Blackout).
- **Add/delete virtual:** `Command::AddScreen { role }` (audience-class roles only — LowerThird/Stream; never Main/Stage) → a new virtual screen with a **generated stable id** (e.g. `stream-2`), `enabled=true`, `deletable=true`, rejected at `MAX_SCREENS`. `Command::RemoveScreen { screen }` → **only if `deletable`** (server rejects deleting any built-in) — also drops that screen's per-screen theme override.
- **Wire (`selahcue-lan`):** the 3 commands as additive snake_case serde tags → `required_permission` `ConfigureOutputs` arm (exhaustive match). Extend the operator screen surface **additively**: a new `screens: Vec<ScreenView>` on `OperatorStateView` (`#[serde(default, skip_serializing_if = "Vec::is_empty")]`), `ScreenView { screen, role, enabled, deletable, theme: Option<String> }`. VERSION unchanged (2); `screen_themes` kept for back-compat.
- **Data (`selahcue-data`):** migration index 12 (v12→**v13**) — a `screen` table `{ screen PK, role TEXT, enabled INTEGER, deletable INTEGER, ordering INTEGER }`; a `screen_repo` (`save_all`/`load_all`); the desktop loads the registry at startup (bounded on load — over-cap rows dropped; a corrupt/empty registry **recovers to the default** main/lower-third/stream/stage, never crashes). Persist on every mutation.
- **Operator (`selahcue-operator/dist/` + `src/main.rs`):** each Screens row gains a right-aligned **Enable toggle** (`set_screen_enabled`), a **"+ Add screen"** control (role picker → `add_screen`), and a **delete** affordance on **virtual rows only** (`remove_screen`); a disabled row dims + its preview shows disabled/black. Register the 3 Tauri commands; reuse the surface-gating/debounce/focus-preservation patterns. NDI/SDI Output-target + Format stay read-only honest "delivery arrives later" affordances.
- **Tests:** controller (add creates a virtual screen; **delete-virtual-only** — a built-in delete is rejected; enable/disable; **disabled → black** compose; **bounded cap** rejects at MAX_SCREENS; deterministic order; remove drops the theme), wire (3 round-trips + **RBAC-denied** for < ConfigureOutputs [Viewer + Monitor] + **VERSION 2 unchanged** + a `ScreenView` round-trip), data (migration v13 round-trip + **recovery** from corrupt/oversized + cap on load), operator headless (toggle disables a row + preview; add creates a row; delete removes a virtual row; a **built-in row has no delete control**), no-leak (registry bounded test).

- Mirror/Grouped/Edge-blend screen types, per-layer Looks, multi-screen groups, per-screen transforms (delay/rotate/crop, FR-044). A SECOND stage/confidence monitor (stage stays a single built-in). Real OS display enumeration for the demo backend (separate story 86ajtxnn1).

Determinism (a stable ordered registry; disabled → the existing safe-black path). **Bounded** (`MAX_SCREENS`) + a bounded-memory test (no-leak rule). Delete-virtual-only + built-ins-never-deleted enforced **server-side**. Migration/recovery: a corrupt/oversized registry recovers to the default, never crashes. `make ci` + operator `node --check` + the committed Chrome + WebKit gates green; 3-OS CI green (verified by conclusion).
