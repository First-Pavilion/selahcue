## What shipped

The Theme Designer surface (`selahcue-operator/dist/index.html` `#surface-theme-designer`, reached from the app menu) is now a working editor: a **theme list** (built-ins + "＋ New (from current)"), a center **`<canvas>` live preview**, and an **Inspector** editing the selected region's (Body / Reference-Title) colour · size · horizontal alignment · line-height · **Fit**, plus the background colour. The preview is **host-rendered for accuracy**: a pure `#[tauri::command] preview_theme(theme_json)` deserializes the JSON to `selahcue_present::Theme`, composes a John 3:16 sample via the **same** `compose_slide → engine::render` path as the audience output, and returns base64 RGBA8 + dims which the webview draws to the canvas via `ImageData` (debounced 120 ms; no host round-trip, no PNG dep). **Apply** sends the additive `Command::SetCustomTheme{theme_json}` (RBAC `ConfigureOutputs`, Operator-only) → the controller deserializes → `presenter.set_theme` + `theme_name="custom"`; malformed JSON → `BadRequest`. The active custom theme is persisted (**migration v9** `session_state.custom_theme`, additive/nullable) and **recovered with precedence** over a named theme. The console theme picker + outputs panel were removed (managed on the Screens surface); all pinned invariants — emergency footer sibling-of-`</main>`, keymap, token needles, structure test — stay intact.

### Refuted (verified NOT real — 7)

- **Verbatim-JSON persistence / no size bound** (wire-persistence) — **pre-empted:** before the verify pass, `set_custom_theme` was changed to persist the **canonical re-serialized** `Theme` (`serde_json::to_string(&theme)`) instead of the raw input. `Theme` is a fixed struct of scalars (no `Vec`/`String`), so the snapshotted payload is bounded to a few hundred bytes and any ignored/duplicate JSON a client padded the (Operator-authorized) payload with is stripped. The verifier read the fixed code and refuted the finding.
- **preview_theme rejection silently swallowed / stale canvas** (a11y) — refuted: preview is a debounced non-critical affordance; a failed preview keeps the last good frame and does not misrepresent the live output (Apply is the state-changing action, and it now surfaces errors — #2).
- **Out-of-order in-flight previews paint a stale frame** (a11y) — refuted: `preview_theme` is a pure fixed-size synchronous host render (sub-ms at 480×270); the 120 ms debounce coalesces bursts and the last edit wins.
- **C-001 preview has zero tests** (contract-tests) — refuted: `render_sample_previews_a_theme_deterministically` proves the exact compose→render path `preview_theme` calls is deterministic and theme-sensitive; the base64 envelope is a thin infallible wrapper.
- **Corrupt persisted custom_theme restore-fallback untested** (contract-tests) — refuted: `set_custom_theme` returns `false` on bad JSON via `let Ok(..) else`, and `restore()` falls back to the named theme; the malformed-JSON no-op is asserted in `set_custom_theme_applies_and_survives_recovery`.
- **render_sample theme-sensitivity proven only by background colour** (contract-tests) — refuted: acceptable for the determinism/sensitivity pin; region typography is covered by the S8-3b compose/alignment tests.
- **Oversized/adversarial theme JSON unbounded** (contract-tests) — refuted: same pre-emptive canonical-serialization fix bounds persistence; the preview/apply dimensions are fixed (480×270), so the framebuffer allocation is input-independent.
