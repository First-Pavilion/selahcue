## What shipped

- **Engine (`present.rs`).** The Presenter gained `main_screen_theme: Option<Theme>` (the `main` audience screen's override) and a private `effective(item)` = **per-screen (`main`) ?? per-item (S8-3d) ?? global** helper that all four compose sites (`stage_themed`/`go_live`/`set_theme`/`set_live_theme`) now use — so `main` with no per-screen theme is byte-identical to before. `set_main_screen_theme` recomposes preview+live; `compose_screen_live(screen_theme)` renders the current live slide **on-demand** (`raster::render(compose_slide(...))`) under any theme, for the SECONDARY screens (no persistent engine); a blank live yields a safe black frame. Re-exported `Rgba`.
- **Controller (`controller.rs`).** `screen_themes: BTreeMap<String,String>` (screen id → **built-in** theme name) + a dirty flag, bounded to `AUDIENCE_SCREENS = [main, lower-third, stream]`. `set_screen_theme{screen,name}` validates the screen + the built-in name (empty = clear); `main` routes to `set_main_screen_theme` (blackout re-applied); secondaries are stored + composed on-demand via `compose_screen(screen)` (blackout-aware). `screen_themes()`/`take/mark/load_screen_themes`.
- **Wire + RBAC.** Additive `Command::SetScreenTheme{screen,name}` + `OperatorStateView.screen_themes: Vec<ScreenThemeView{screen,theme}>` (serde `default` + `skip_serializing_if`, so pinned v2 fixtures stay byte-identical when empty) → `ConfigureOutputs` (Operator-only). The internal `OperatorView.screen_themes` is a `ScreenThemeView` (object shape, not tuples).
- **Persistence + recovery.** Migration **v12** `screen_theme(screen PK, theme_name)` (older DB opens empty) + a transactional `screen_theme_repo` (save_all/load_all). The desktop loads on startup AFTER the library AND after restore (so `main` recomposes restored content), and saves on `take_screen_themes_dirty()` in the autosave loop + the clean-exit flush (re-armed on failure). `load_screen_themes` keeps only known screens with a known built-in name.
- **Frontend (Screens page, `app.js`).** A per-screen Theme picker (`themePickerFor(screen)`) wired to `invoke("set_screen_theme",{screen,name})` (NOT the global) — the main audience row plus virtual `lower-third`/`stream` rows each get one; a "◈ Follow global" entry clears the override. Physical NDI/stream delivery for the secondaries is an honest seam note. The main window still renders the `main` screen physically.

## Findings and dispositions

| # | Lens | Sev | Finding | Disposition |
|---|------|-----|---------|-------------|
| 1 | engine | **MED** | **`main`'s per-screen theme could go stale.** `set_screen_theme` resolved the name via `resolve_theme_name` (which also accepted a **saved-library** name) and cached the resulting concrete `Theme` in the Presenter. If that saved theme was later **edited** (`SaveTheme` again) or **deleted** (`DeleteTheme`), the presenter's cached `main_screen_theme` never refreshed — the physical `main` projector kept rendering the old design (or a since-deleted one), diverging from `compose_screen(main)` and the map. Reachable via the wire (`SetScreenTheme` + `SaveTheme`/`DeleteTheme`), though not via the shipped built-ins-only picker. | **Fixed:** `set_screen_theme` now accepts a **built-in name only** (`Theme::builtin`), exactly like the sibling `set_item_theme` (S8-3d) — built-ins are immutable, so the cached theme can never be edited/deleted out from under the output. `resolve_theme_name` was removed; `compose_screen`/`load_screen_themes` also resolve built-ins only. Assigning a SAVED custom theme per-screen becomes an honest follow-up (it also needs a re-sync-on-library-change path). New `test_controller` assertion: a real saved-library name is rejected for a screen. |
| 2 | frontend | **MED** | **No "follow global" option → a per-screen theme couldn't be cleared from the UI.** `themePickerFor` built options only from the built-in names; there was no blank entry and `onchange` never sent the empty name. Once a screen was themed, the operator could not un-set it back to the global — a later global switch silently no longer reached that screen. The backend's clear path (`SetScreenTheme` with empty name) was tested and pinned but **unreachable** from the operator's only entry point. Diverged from the per-item picker (S8-3d), which has a blank "follow global". | **Fixed:** `themePickerFor` now prepends a **"◈ Follow global"** option (empty value → the backend clear), selected when the screen has NO explicit entry (membership test on the map, not the value — so "explicitly classic" is distinguished from "unset, following classic"). Verified headlessly: a screen with an override shows it selected; an unset screen shows "◈ Follow global" with an empty value. Pinned in `test_tokens`. |

### Refuted / clean lenses

- The **persistence** and **wire/RBAC** lenses raised **no findings** — migration v12 is additive + upgrade-tested, the repo is transactional + ordered, the desktop load/save order is correct (library → restore → screen-themes), and the view serializes as `{screen,theme}` objects (the tuple-vs-object trap from the prior batch was avoided from the start and is pinned by a fixture).
