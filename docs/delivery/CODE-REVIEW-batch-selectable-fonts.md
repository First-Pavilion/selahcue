# Code Review — Batch: Selectable system fonts (86ajq6fxt)

- **Scope:** story `86ajq6fxt` — let a theme select a font from those installed on the render machine (no bundled fonts added), while keeping the bundled Noto Sans as the **deterministic default** (a theme with no font renders byte-identically on every OS — NFR-014, unchanged). The Theme Designer's "Font" control becomes a real picker. Executed via `/goal` (`TASK-86ajq6fxt-selectable-fonts.md`, validator PASS). **No new wire command and no migration** — the font rides in the existing theme JSON (`SetCustomTheme`/`SaveTheme`).
- **Method:** an adversarial Workflow review (`wf_a5313bef-b7e`, 3 independent lenses → per-finding adversarial verify, **7 agents**, 523k tokens). Lenses: determinism/fallback/no-leak · theme-serde/no-wire-drift · frontend-picker. Every finding independently confirmed-or-refuted (default REFUTED). No self-approval.
- **Outcome:** **4 raised → 3 CONFIRMED → all fixed; 1 refuted.** 0 HIGH; 1 MEDIUM; 2 LOW.

## What shipped

- **Engine (`scene.rs` + `raster.rs`).** `Layer::Text` gains `font: Option<FontName>` (additive serde). `FontName` is a `Copy` bounded string (a newtype over `arrayvec::ArrayString<64>`) so `Layer` + `Theme` stay fixed-size `Copy` PODs; a **validating** Deserialize routes every wire value through `FontName::new` (trim + reject empty/over-long). `raster.rs`: a **lazy** `TextCtx.system_fs` — `build_bundled_fs()` (the unchanged deterministic default path) vs `build_system_fs()` (bundled + `load_system_fonts()`); `draw_text` + `measure_line_width` take the font (`None` → the bundled fs, byte-identical to before; `Some` → the lazy system fs via `Family::Name`); `tick()` drops `system_fs` on reset (bounded). `system_font_families()` enumerates installed families (sorted, deduped, bounded).
- **Theme + compose (`theme.rs` + `compose.rs`).** `Theme.font: Option<FontName>` (additive `skip_serializing_if`), threaded through `compose` (measure + `Layer::Text`) for the title + body regions; the stage/confidence monitor stays on the bundled default.
- **Enumeration + frontend.** A `system_fonts()` Tauri command; the Theme Designer's Font control is a real `<select>` populated from it (+ a "Noto Sans (default)" entry that clears the field for a byte-stable default), reflecting a saved theme's font even when it isn't installed on this machine.

## Findings and dispositions

| # | Lens | Sev | Finding | Disposition |
|---|------|-----|---------|-------------|
| 1 | determinism | **MED** | **`#[serde(transparent)]` bypassed `FontName::new` on deserialization.** The wire path (`SetCustomTheme`/`SaveTheme` run `serde_json::from_str::<Theme>`) accepted arbitrary JSON, so `{"font":""}` deserialized to a themed `Some("")` — it took the **non-deterministic** system-font path (`Family::Name("")`, loading system fonts) *and* re-serialized as `"font":""` (not skipped, since `Some`), so a theme that means the default was neither the default render nor byte-stable; `{"font":" Arial "}` wasn't trimmed → `Family::Name(" Arial ")` missed the installed "Arial" → wrong fallback. | **Fixed:** replaced the derived transparent (de)serialize with a **validating** manual impl — Deserialize funnels the string through `FontName::new` (trim + reject empty/whitespace/over-long, erroring via `serde::de::Error::custom`), Serialize emits the trimmed `as_str()`. Now the wire enforces the same invariant as the constructor; `{"font":""}` is rejected and `" Arial "` normalizes to "Arial". New `test_compose` assertion covers empty/whitespace/over-long rejection + the trim. |
| 2 | determinism | LOW | **`set_*_family("Noto Sans")` was dead code + a false guarantee.** Those generic-family settings are only consulted for `Family::SansSerif`/`Serif`/…, which the themed path never emits (it uses `Family::Name`). So a missing font actually falls back through cosmic-text's chain to the **OS default font** (`.SF NS` on macOS, `Segoe UI` on Windows), *not* the bundled Noto Sans the comments/tests claimed — though it is always a readable, deterministic-per-machine font (never tofu/blank/panic). | **Fixed:** removed the five dead `set_*_family` calls and corrected the code + test comments to state the honest guarantee — a missing font degrades to a **readable platform font** (Noto Sans on Linux, the OS UI font elsewhere), deterministic per machine, never tofu. The behaviour (safe readable fallback) is unchanged and correct; only the misleading claim is gone. |
| 3 | frontend | LOW | **The picker blanked a saved theme's font when it isn't installed here.** A theme designed on another machine (font "Helvetica Neue") opened on a machine without it → the `<select>` had no matching option → showed blank, so the operator couldn't see the theme's font and could accidentally clear it on the next interaction. | **Fixed:** `tdEnsureFontOption` injects a transient "<family> (not installed here)" option when the theme's font isn't enumerated (in `tdSync` + after `tdLoadFonts`), so the picker faithfully reflects + preserves it. Verified headlessly: a theme with an un-installed font shows "Helvetica Neue (not installed here)" selected (value preserved). Pinned in `test_tokens`. |

### Refuted (verified NOT real — 1)

- **The single `SwashCache` shared by the bundled + system `FontSystem` could collide** — refuted: `build_system_fs` loads the bundled font FIRST (same face id), so the shared glyph cache is collision-safe; and the caches key on the shaped glyph, not the fs — no cross-fs mismatch.
