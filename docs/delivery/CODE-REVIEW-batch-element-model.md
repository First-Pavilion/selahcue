- **Scope:** story `86ajq6j2q` (epic `86ajq6j01` Canvas Editing) — the **engine foundation** for on-canvas editing: extend the render/theme model from the fixed title/body regions + single `Band` to an **ordered list of layered elements**, each with a per-mille rect + **opacity** + a **z-index** relative to the text, composited back-to-front. The **image** kind (needs S8-6 sandboxed decode, `86ajpzhbc`/`86ajq6j49`), the **text** kind, and all on-canvas authoring UI (`86ajq6j4p`/`86ajq6j64`) are the dependent stories — so this batch is the engine model + rendering + tests, not the Designer UI. Executed via `/goal` (`TASK-86ajq6j2q-element-model.md`, validator PASS, 4/4 mandatory). **No new wire command and no migration** — elements ride in the existing theme JSON (`SetCustomTheme`/`SaveTheme`).
- **Method:** an adversarial Workflow review (`wf_8475bc43-098`, 3 independent lenses → per-finding adversarial verify, **7 agents**, 501k tokens). Lenses: model / Copy-ripple / bounded · compose z-order+opacity+determinism · persistence / recovery / no-drift. Every finding independently confirmed-or-refuted (default REFUTED). No self-approval.

## What shipped

- **Model (`theme.rs`).** `Theme.elements: Vec<Element>` (`#[serde(default, skip_serializing_if = "Vec::is_empty")]` → a default theme's JSON is byte-identical). `Element` is an internally-tagged (`#[serde(tag = "kind")]`) enum with a `Shape { rect (per-mille x/y/w/h), fill, border, border_permille, opacity: u8, z: i16 }` variant — all-scalar, so `Element: Copy`. `Theme` now derives **`Clone` (not `Copy`)** because it holds a `Vec`; `RegionStyle`/`Band`/`FontName`/`Element` stay `Copy`. Bounded: `MAX_ELEMENTS = 64`, enforced at every ingress. The enum is additive so `Text`/`Image` variants land later without a wire break.
- **Compose (`compose.rs`).** `element_layers(element, w, h)` renders a `Shape` as `Layer::Fill` layers (a fill rect + up to 4 border edges, per-mille like `band_layers`), multiplying the whole-shape opacity into each colour's alpha (src-over blend already handles translucency). `compose_slide` stable-sorts the elements by `z` and renders `z < 0` **behind** the text regions (after the band), `z >= 0` **in front**; within a group, list order. A theme with no elements is unchanged.
- **Copy→Clone ripple.** Just **3 sites** in `present.rs` (`self.live_theme = self.staged_theme.clone()`, the `theme()` + `main_screen_theme()` getters clone); everything else compiled unchanged. Workspace + operator build.
- **Persistence + bound.** Elements ride in the theme JSON (`custom_theme` / `saved_theme`); `set_custom_theme` + `save_theme` reject `elements.len() > MAX_ELEMENTS`, and (post-review) so does the startup `load_saved_themes`. **No migration** — `protocol.rs`/`migrations.rs`/`rbac.rs` untouched, `target_version` unchanged, pinned v2 fixtures byte-stable.

## Findings and dispositions

| # | Lens | Sev | Finding | Disposition |
|---|------|-----|---------|-------------|
| 1 | model-ripple-bounded · persistence | **MED** ×2 | **`load_saved_themes` did not enforce `MAX_ELEMENTS` — the one theme-with-elements ingress that was unbounded.** Every write path is capped: `set_custom_theme` + `save_theme` reject over-cap, and `restore()`'s custom theme routes through `set_custom_theme`. But the startup store load only filtered on name-nonempty, name length, and JSON validity — never `elements.len()`. The `saved_theme.theme_json` column is local SQLite TEXT (not transport-bounded; the 64 KB LAN frame cap only guards the wire paths). A tampered / backup / version-skewed row carrying, say, 200 000 `Shape`s would be accepted at launch, then resolved (per-item override, `"main"` screen entry, or operator selection) with no bound, and **every rendered frame** would build a 200 000-pointer Vec + stable-sort + push ~1M `Layer::Fill` — the exact unbounded per-frame cost `MAX_ELEMENTS` exists to prevent. (Both MEDIUM lenses independently landed on this same defect.) | **Fixed:** the `load_saved_themes` filter now also bounds `serde_json::from_str::<Theme>(json).map(\|t\| t.elements.len() <= MAX_ELEMENTS).unwrap_or(false)`, reusing its single deserialize — an over-cap row is **dropped** defensively, consistent with the existing name-length / count / JSON-validity guards (and the doc comment's "a corrupt store can never exceed the bound" promise). Regression added to `saved_theme_library_is_bounded_and_load_drops_bad_entries` (a valid-name/valid-JSON but over-cap row is dropped). |
| 2 | compose-zorder-opacity-determinism | LOW | **A translucent element border double-blended at the four corners.** `element_layers` pushed four full-length border edges (top/bottom full width, left/right full height); the `bt×bt` corner squares were covered by two edges each, so `raster::blend` (src-over) composited them **twice**. Idempotent for an opaque border (why `band_layers` never showed it) — but this batch multiplies the shape opacity into the border alpha, making a translucent border a first-class case, so a `< 255`-alpha border rendered its four corners visibly **brighter** than the straight edges (coverage `1-(1-α)²`). Deterministic, purely cosmetic. | **Fixed:** left/right edges now span the full height and **own the corners**; top/bottom cover only the interior width (`w − 2·bt`, guarded `.max(0)`). Every border pixel blends **exactly once** → uniform corners for any opacity; opaque borders are visually identical; a no-element / no-border theme is byte-identical (parity holds). New regression `a_translucent_element_border_paints_its_corners_uniformly` (corner == straight top/left edge; single-blend, not opaque). |

### Refuted (verified NOT real — 1)

- **An unknown element `kind` fails the WHOLE `Theme` deserialize — a newer peer's saved theme is dropped entirely on an older build.** Refuted: this is inherent to the additive internally-tagged-enum seam (an old build cannot know a future `Image`/`Text` variant), not a defect introduced by this batch, and dropping-to-default is the **intended honest degradation** — the alternative (silently discarding just the unknown element) would render a theme its author never designed. The batch's scope is shape elements; forward-compat of future kinds is a concern for the story that adds them.
