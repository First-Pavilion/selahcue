# C4 saved-note PDF source evidence — 2026-11-11

This slice exports the accepted saved sermon notes offline. It is source/local-fixture evidence, not Windows pilot acceptance or a distribution approval.

## Contract

The Tauri command accepts only `transcript_id`, calls the existing permission-checked backend load once, distinguishes absence from a failed read, and moves that immutable accepted snapshot to a blocking worker. A process-wide permit bounds export concurrency to one and stays with that worker through native Save and publication. No controller lock is retained while rendering, showing the dialog or writing. Pending regeneration and unsaved form contents are not command inputs. The edit UI disables export with save guidance; the pending view explicitly labels the accepted saved-note export. No export code writes the note/transcript database.

Strict typed JSON decoding accepts the documented legacy array and envelope forms before applying shared requested-empty caveat semantics. Malformed or ambiguous structures refuse export. The PDF retains outline hierarchy, all listed references, embedded-reference verdicts, incomplete-verification warnings, the AI label and stored disclosure. Address checks use the same default bundled Bible (KJV), and their quotation-accuracy limitation remains explicit. Note creation time is not relabelled as a sermon date; absent trustworthy dates are omitted. Internal transcript identifiers appear only in the native receipt.

`printpdf = 0.12.8` has default features disabled: no HTML, browser renderer, remote assets or Azul layout feature. Already-locked `harfrust = 0.5.2` performs actual native OpenType shaping; NFC only establishes canonical-equivalent extraction text. Graphemes are shaped once, never split between lines/fonts; unsupported glyphs, unrepresentable Unicode mappings, control characters and clusters longer than 64 scalars refuse safely. One unchanged full Noto Sans Regular font is embedded and reused for the document. Upstream bytes, hashes and OFL notices are under operator `assets/notes-pdf`. The font is compiled into the native executable; `tauri.conf.json` explicitly bundles its LICENSE and provenance README under `licenses/notes-pdf/`. No engine font changed and no license appendix is inserted into sermon notes.

Bounds: 128 KiB combined rendered input before JSON allocation, one concurrent export, at most 500 pages enforced during layout, and 16 MiB serialized PDF before publication. These are bounds on work/output, not a proof of peak memory on the target device.

## Publication boundary

Native Save authorizes its selected path; it does not return a file-ID/overwrite-confirmed flag. The helper observes target/parent identities and type, size and mtime, creates an exclusive randomized sibling (Unix mode 0600), writes and syncs all bytes, closes the writer, then rechecks. Unix operations are anchored to an opened parent directory with no-follow component traversal. An initially absent target uses atomic no-replace so a late arrival survives. An unchanged observed existing regular target uses same-directory atomic replacement. Windows uses MoveFileExW, never ReplaceFileW or remove-then-rename, and refuses detected reparse links, network/unknown volumes and anything outside a local fixed NTFS boundary.

Success is the publication commit point; later diagnostics/cancellation do not claim that the old target survived. Pre-commit errors and supported local rename failures preserve the target; cleanup only removes a stage whose identity is still positively owned. A changed namespace may leave an orphan rather than delete a substitute. Rechecks are not destination-ID compare-and-swap: hostile/same-user namespace changes, concurrent external writes, hardware failure and crash/power-loss durability remain outside this guarantee. Windows inherits directory permissions for newly created stages. Native Windows qualification remains required.
