## What shipped

- **Model (`scene.rs`).** Additive `Layer::Image { rect, source: MediaRef, #[serde(default, skip_serializing_if)] opacity: u8 }` (internally-tagged enum → Fill/Text JSON byte-unchanged; `Eq` preserved via a `u8` opacity). `MediaRef` is a bounded (`CAP=1024`) validated reference with a validating Serialize/Deserialize (trim + reject empty/over-long/NUL, the `FontName` pattern) — the wire/IPC can't smuggle an unbounded or malformed reference. **Decoded pixels are NOT carried here** — the scene stays small + serde-cheap.
- **Decode (`media.rs`, new).** `decode_png(bytes, &DecodeLimits) -> Result<DecodedImage, DecodeError>` via the pure-Rust `png` crate: a PNG-signature allowlist + `set_limits` + `normalize_to_color8`, a **dimension AND pixel-count cap enforced before allocating** the output buffer (decompression-bomb defense, FR-173), normalising Grayscale/GrayscaleAlpha/Rgb/Rgba → straight RGBA8 (no gamma/ICC/premultiply → byte-identical cross-OS, NFR-014). `Result`-based, no unwrap/panic. **PNG only** this batch; other formats → the placeholder (a documented later-format seam).
- **Raster (`raster.rs`).** A `Layer::Image` arm → `draw_image` resolves the reference through a **bounded decode cache** (thread-local, capped by `MAX_IMAGE_CACHE_ENTRIES=64` AND `MAX_IMAGE_CACHE_BYTES=256 MiB`, bounded reset on breach; failed decodes cached as `None`) and either `blit_image` (integer nearest-neighbour scale to the rect + whole-layer opacity into src alpha + the existing integer `blend` src-over, `fill_rect` clip math — a pure integer function → deterministic) or `draw_placeholder` (a distinct, non-black, deterministic panel — never blank, never crash).
- **Determinism / parity.** A no-image scene is byte-identical to before; the GPU compositor **skips `Layer::Image`** exactly as it already skips `Text` (GPU-native images are a later batch), so the parity oracle (six Fill-only scenes) is unchanged and CPU↔GPU stays SSIM ≥ 0.99. Byte-parity is asserted only on the CPU raster.
- **ADR-0018.** Bounded in-process still-image decode; refines ADR-0016 sequencing; honest residual T12 posture; the `Layer::Image` reference→pixels boundary is the plug point the sandboxed worker later fills unchanged.

## Findings and dispositions

| # | Lens(es) | Sev | Finding | Disposition |
|---|------|-----|---------|-------------|
| 1 | determinism-parity-blit · placeholder-fault-isolation | **MED** | **`draw_placeholder` did unchecked i32/i64 arithmetic on the unvalidated layer rect → an integer-overflow PANIC in debug/test builds.** Unlike its overflow-safe siblings (`fill_rect`/`blit_image` clamp in i64, `draw_text` uses `saturating_add`), the new placeholder computed the border edges as raw i32 `x + w - bt` and the diagonal metric as `u*rh - v*rw` in i64. A layer `Rect` is never validated (only `frame.width/height` pass through `is_renderable`), and the placeholder is exactly the path a **missing/corrupt/unsupported** image reaches. Concrete repro (both verifiers, through the real `render()` path): `Layer::Image { source: MediaRef("/no/such/file.png"), rect: Rect::new(i32::MIN, 0, u32::MAX, u32::MAX) }` (or `x≈2e9, w≈2e9`, so `x+w > i32::MAX`) in any renderable frame → `x + w` / `u*rh` overflow → with the workspace's default `overflow-checks=true`, the render thread **panics** — the exact "a crafted image contains to the placeholder, never crashes" guarantee (FR-173/NFR-024) this batch claims. Latent: every existing test used a tiny benign rect. | **Fixed:** rewrote `draw_placeholder` to be overflow-safe like its siblings — the base fill goes through `fill_rect` (i64-clamped); the border + diagonal are computed only within the **on-screen clipped span** (every coordinate ≤ frame dimension ≤ `MAX_DIMENSION`), rect edges in **i64** (i32 + u32 can't overflow i64), and the diagonal metric promoted to **i128** so `u*rh` can never overflow. Added the regression `the_placeholder_never_panics_on_an_adversarial_image_rect` (renders `i32::MIN/u32::MAX`, `x+w`-overflow, and negative-origin rects without panicking; the visible base is non-black). |

### Refuted (verified NOT real — 5)

- **Arbitrary local-file read via `MediaRef` (path traversal).** Refuted: no wire/authoring path sets a `MediaRef` this batch (`Element::Image` is the deferred `86ajq6j49`), so there is no untrusted-path ingress now; import-path canonicalization (FR-138) is the named seam for that follow-up. Mechanically accurate, no live defect.
- **`decode_png`'s bomb guard is caller-limit-controlled; the pre-`next_frame` allocation isn't independently bounded.** Refuted: the shipped render path always uses `DecodeLimits::default()` (via the cache) which caps dimensions + pixels + the png crate's own `set_limits` before allocation; `decode_png` takes limits by design (for tests). Not reachable as a defect.
- **A failed/missing decode is cached permanently (a transient failure becomes a sticky placeholder).** Refuted as a defect for this batch — the mechanism is real but the cache clears on the bounded reset / `reset_image_cache`, and images are set pre-service. Noted as an R2 cache-invalidation/TTL seam.
- **The byte-cap invariant relies on the un-enforced coupling "single image < budget".** Refuted: no input can violate it against the committed code — `max_pixels*4 = 160 MiB < MAX_IMAGE_CACHE_BYTES = 256 MiB`, and the clear-before-insert keeps `total_bytes ≤ budget` always.
- **`png 0.17` double-carries PNG (+`bitflags 1.x`) in the operator workspace alongside `png 0.18`.** Refuted: the premise is wrong against the operator lockfile (the operator pins `selahcue-engine`, gaining exactly one `png 0.17.16` line; no conflicting double-carry).
