# Code Review — Batch: font weight + letter-spacing in the Theme Designer (86ajq3225, refine #5)

- **Scope:** enable the Theme Designer's previously-disabled **Weight** and **Letter-spacing** fields so a theme can set a font **weight** (Regular…Black) and **letter-spacing** (tracking) that the audience output renders — deterministically (NFR-014), additively (no wire/migration break), for both the bundled default font (deterministic faux-bold, since cosmic-text 0.12 does **not** synthesize bold for the single-weight bundled Noto face — verified empirically in Iter 0) and a per-machine system font (its real weight face). Theme-level `weight: u16` (skip-if-400) + `letter_spacing_permille: i16` (skip-if-0) on `Theme`; `TextStyle { weight, letter_spacing_px }` on `Layer::Text` as `Option<TextStyle>` (skip-if-default → byte-identical default JSON); `compose` threads them (per-mille → px via the region cell); the operator `dist/` enables + wires the two fields. Executed via `/goal` (`TASK-86ajq3225-font-weight-letter-spacing.md`, validator PASS). Additive across scene/raster/theme/compose/designer; **no wire/RBAC/migration change** (`VERSION` unchanged); GPU-skip unaffected (Text was already skipped).
- **Method:** an adversarial Workflow review (`wf_66ba08ec-5b7`, **3 lenses** → refute-by-default verify, ultracode; 9 agents, 494k tokens). Lenses: **shaping determinism / faux-bold / letter-spacing / bounded** · **model / serde / no-drift** · **designer wiring**.
- **Outcome:** **6 raised → 4 confirmed → 2 refuted**, where the 4 confirmations collapse to **2 distinct defects** (each independently found by two lenses). **Both fixed + pinned by a new regression test.** The 2 refutations were correct rejections (an intentional cull guard; a cosmetic, app-unproducible display gap).

## Findings and dispositions

| # | Lens(es) | Sev | Finding | Disposition |
|---|----------|-----|---------|-------------|
| 1 | shaping-determinism **+** model-serde | MEDIUM | **Panic regression:** `let ls = letter_spacing_px.clamp(-2 * px as i32, 2 * px as i32)` (`raster.rs:741`) computes the clamp bound from the raw `px: u32`. For `px ≥ 2³⁰` the `2 * px as i32` overflows i32 → **DEBUG** panics `attempt to multiply with overflow`; **RELEASE** wraps so `min > max` and `clamp` panics. Reachable via a crafted/deserialized `Layer::Text` (`render()`/`Layer` are public); fires **even at the default style** (`ls == 0`) because the bound is evaluated unconditionally — so it also regressed the historical default path. Pre-diff `draw_text` was pure-f32 for `px` and never panicked; the batch's own bounded test fixed `px` small (120) and only varied spacing, so the extreme-`px` path was untested. | **Fixed.** Bound now computed in i64 + saturated to i32: `let bound = ((px as i64) * 2).min(i32::MAX as i64) as i32; let ls = letter_spacing_px.clamp(-bound, bound);`. New regression test `extreme_px_text_does_not_overflow_panic` (`test_raster.rs`) renders `px ∈ {2³⁰, 1.5e9, u32::MAX}` × `{None, Some(spaced)}` and asserts no panic + a bounded framebuffer. |
| 2 | shaping-determinism **+** model-serde | LOW | **Wrong-render (right-edge clip):** `measure_line_width` gained a `weight` arg but **not** letter-spacing, so the auto-fit wrap + ShrinkToFit binary search size the cell against the **untracked** width, while `draw_text` then adds `(glyphs−1)·ls` of tracking at render — so a tracked near-full-width line fits the fit but **clips on the right** at render, violating the zero-content-loss auto-fit guarantee (FR-010). Concrete: `permille=100` (0.1 em) at cell=100 → ls=10px; a 20-char line is drawn ~190px wider than its region and the trailing glyphs are culled. Reachable via the operator letter-spacing field (up to 1.0 em). | **Fixed.** `wrap_at` (`compose.rs`) now budgets for tracking: `ls_add = max(0, cell·permille/1000)` is charged **once per glyph** (word width `+ chars·ls_add`) **and once per inter-word space** (`space_w + ls_add`) — a conservative estimate that never under-counts the drawn width (only positive tracking widens; negative only tightens → still fits), staying O(words) so no Go-Live stall. New regression test `tracked_text_fits_its_region_no_right_clip` (`test_compose.rs`) composes a long verse at `permille=100` and asserts every emitted line's **tracked** width (`measure + (glyphs−1)·ls_px`) fits its region + no word dropped. |
| 3 | shaping-determinism | (raised) | "Negative tracking silently disables the frame-bounded left-to-right glyph cull." | **Refuted — the guard is intentional & correct.** `if ls >= 0 && pen_x >= clip_right { break }` (`raster.rs:815`) exists precisely because negative tracking moves later glyphs left (non-monotone pen positions), so a left-to-right break would drop *visible* glyphs. Work stays bounded by input length; the authoritative per-pixel clip governs the actual pixels; determinism intact. Confirmed by `extreme_letter_spacing_is_bounded_no_panic` (i32::MIN/MAX). At most a bounded O(total glyphs) cost for one narrow raw-API config unreachable through the wrapping theme path. |
| 4 | designer-wiring | (raised) | "Weight `<select>` shows blank for an out-of-enum weight (no `tdEnsureFontOption` equivalent)." | **Refuted — cosmetic + app-unproducible.** The weight value space is a **closed enum** the operator fully controls (built-ins pinned to 400; the sole writer emits only {400→deleted, 600, 700, 900}); every app-producible value matches an `<option>`, so the control never blanks in normal use. Injecting `500` needs hand-editing an on-disk theme JSON (Import/Export are no-op stubs); even then `tdTheme.weight` is preserved faithfully across preview/render/save — no functional consequence. The font↔weight disanalogy is invalid (fonts are an OPEN set; weight is closed). Not a wrong-render / serde-drift / wiring defect. |

**2 distinct real defects, both fixed and regression-tested.** Both were determinism-safe (integer/f32, deterministic) and neither touched the wire — the panic was a bounded-invariant regression, the clip a fit-vs-render width mismatch, both in the newly-added letter-spacing path.

## What shipped (the fixes)

- **`raster.rs` (#1):** the letter-spacing clamp bound is computed in i64 and saturated to i32 (`((px as i64) * 2).min(i32::MAX as i64) as i32`), so any `px: u32` is safe — `draw_text` cannot panic on any input, restoring the bounded/no-panic contract for the default path too.
- **`compose.rs` (#2):** `wrap_at` folds positive letter-spacing into both the per-word width and the inter-word space width, so the auto-fit picks a cell whose **tracked** lines fit the region — no right-edge clip. Conservative (never under-counts), O(words), monotone (binary search preserved).
- **Tests:** `extreme_px_text_does_not_overflow_panic` (engine) + `tracked_text_fits_its_region_no_right_clip` (present) pin both fixes.
