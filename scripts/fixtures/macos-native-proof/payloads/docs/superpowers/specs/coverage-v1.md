## 3. Source indexing v1

Validate the existing admission contract first: HTTP8MiB, source<=400,000 Unicode scalars and UTF-8<=1,600,000 bytes, no lone surrogates, nonblank source. Do not silently shorten any accepted source.

Let S be the exact decoded source scalar sequence, N its length and p=0. While p<N:

1. If N-p<=1,600, choose q=N.
2. Otherwise choose the greatest boundary q in [p+800,p+1,600] satisfying either S[q-1] is LF, or S[q-1] is ASCII space/tab and S[q-2] is one of `.`, `!`, `?`. If none, q=p+1,600. This is a mechanical grouping rule, not linguistic sentence recognition.
3. Emit S[p:q] and advance p=q. IDs in order are `B0000`, `B0001`, …, exactly four decimal digits after B. Maximum512 blocks; overflow refuses without inference. At the admitted source bound this algorithm normally needs at most500 blocks.

Retain original scalar and UTF-8 offset boundaries locally. No newline conversion, Unicode normalization, whitespace trimming, overlapping content, omission, ellipsis or inserted source text. Concatenation equals S exactly. A combining sequence or sentence may straddle a block: references can cross blocks and quotation matching concatenates exact block strings. Do not claim segmentation finds propositions or importance.

The user-message content is a compact JSON serialization of `{schema_version:"1",options:<exact NoteOptions>,source_blocks:[{id:<B-id>,text:<exact slice>},...]}`. Source text is present exactly once. No original-source duplicate, source rubric, expected answers, previous draft, external resource, history or tool output enters the request. IDs/text inside a source string are untrusted quoted content, not structural entries. Source IDs are generated by the server. Keep offset index out of the model request because the model needs IDs, not inferred timestamps.
