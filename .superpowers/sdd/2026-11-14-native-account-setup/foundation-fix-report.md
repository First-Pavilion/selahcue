## Coherent ownership correction

The prior exact-send-generation response-custody assumption was wrong for concurrent progress on the same immutable bound operation. The response must own the nonce/path/protocol/mode/identity/expected binding, rather than the most recent revision written by any identical retry. The accepted foundation ruling supersedes that earlier Task 3 assumption.

The stable app-data account-session-custody lock now covers short local metadata/session/device-custody ownership decisions. All controller metadata saves cooperate with it. Dispatch validates the exact loaded snapshot, saves the session and advances the send generation within this fence. A stale signer cannot replace the dispatch winner's restart authority. Every sender still CAS-advances before HTTP; a stale request cannot send after retirement.

Accepted responses reload current metadata under this fence and require the identical immutable pending operation and compatible device binding. Public identity is saved before device custody. A token-bearing response saves and retires locally within that fence; a no-secret replay validates an existing bearer against the exact device outside the fence, then rechecks identity before retirement. Missing or rejected bearer custody retains the nonce and account authority because the original token-bearing response may still arrive. A different operation or binding remains fenced. An accepted response is held only in the existing bounded native memory window; secrets remain absent from metadata and DTOs.

Cleanup validates its loaded metadata and captures its exact account session under the same fence, then persists a non-secret `cleanup_reserved` boolean before HTTP. Cooperating activation writers refuse this reservation. Confirmation clears only the matching account entry and clears the reservation. Restart can retry the reservation, including clearing a leftover reservation if the entry is already absent. The final view reloads committed metadata so successful cleanup does not leave a stale warning. A newly returned login session that never reached custody can be revoked independently as this invocation's unused credential.

No HTTP runs under the local ownership fence, metadata writer lock, view lock, or presentation lock. No lock is held over renderer work. This is coordination among cooperating native writers, not a transaction across the filesystem and OS credential service, nor protection against arbitrary external keyring tools.
